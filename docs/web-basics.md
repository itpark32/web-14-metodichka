# 1. Как работает интернет, HTTP и браузер

<p class="reading-time">Чтение: 8 минут</p>

Когда пользователь вводит адрес, браузер должен найти сервер, запросить ресурсы и превратить полученные файлы в страницу.

!!! abstract "Фокус"
    - **Нужно знать:** клиент, сервер, URL, DNS, запрос и ответ.
    - **Часто в работе:** кэш, вкладка Network, последовательность загрузки страницы.
    - **Достаточно узнавать:** подробности TCP, TLS и устройство сетевых пакетов.

## Клиент и сервер

Браузер выступает клиентом: инициирует запрос и показывает результат. Сервер принимает запрос, выполняет свою логику и возвращает ответ. Один документ обычно собирается из нескольких ресурсов: HTML, CSS, JavaScript, шрифтов и изображений.

```text
браузер -> HTTP-запрос -> сервер
браузер <- HTTP-ответ  <- сервер
```

Сервер не обязательно является одним физическим компьютером. Между клиентом и приложением могут находиться CDN, прокси и кэш.

## Из чего состоит URL

```text
https://shop.example.com:443/catalog?sort=price#offers
└─scheme─┘ └────host─────┘    └path─┘ └query───┘ └fragment┘
```

- `https` задает протокол;
- `shop.example.com` является именем хоста;
- `443` обозначает порт и обычно не пишется для HTTPS;
- `/catalog` является путем к ресурсу;
- `sort=price` передает параметры запроса;
- `#offers` указывает фрагмент внутри уже загруженного документа и серверу обычно не отправляется.

## Что происходит после Enter

1. Браузер разбирает URL.
2. DNS помогает получить сетевой адрес сервера по доменному имени.
3. Устанавливается защищенное соединение для HTTPS.
4. Браузер отправляет HTTP-запрос.
5. Сервер возвращает статус, заголовки и тело ответа.
6. Браузер разбирает HTML и запрашивает связанные ресурсы.
7. Из HTML строится DOM, из CSS строится модель стилей.
8. Браузер рассчитывает расположение элементов и рисует страницу.
9. JavaScript может изменить DOM и запустить новые запросы.

Это упрощенная модель, которой достаточно для отладки большинства учебных проектов.

## HTTP в одном примере

```http
GET /catalog HTTP/1.1
Host: shop.example.com
Accept: text/html
```

```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8

<!doctype html>...
```

Метод сообщает намерение запроса, статус показывает результат, заголовки описывают данные, тело содержит ресурс.

!!! warning "Ловушка: интернет и Web не одно и то же"
    Интернет является инфраструктурой передачи данных. Web является одной из систем поверх интернета и использует URL, HTTP, HTML и браузеры.

## Network в DevTools

Откройте DevTools, перейдите в Network и перезагрузите страницу. Для каждого запроса можно увидеть:

- адрес и метод;
- статус;
- время выполнения;
- заголовки запроса и ответа;
- размер и содержимое ответа;
- источник: сеть или кэш.

Красный запрос не всегда означает проблему JavaScript. Возможны неверный путь, ответ 404, запрет CORS или недоступный сервер.

## Как ответить на интервью

> Браузер является HTTP-клиентом. После ввода URL он получает адрес сервера через DNS, устанавливает соединение, отправляет запрос и получает ответ. Затем разбирает HTML, загружает CSS, JavaScript и изображения, строит DOM, рассчитывает раскладку и рисует страницу.

## Мини-практика

Откройте свой проект в Network, отключите кэш и перезагрузите страницу. Найдите запросы HTML, CSS, JavaScript и изображения. Для каждого назовите URL, статус, тип содержимого и инициатора.
