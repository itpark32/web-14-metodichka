# 30. HTTP, REST API и Network

<p class="reading-time">Чтение: 10 минут</p>

Fetch отправляет запрос, но для уверенной работы нужно понимать метод, адрес, заголовки, тело и статус ответа.

!!! abstract "Фокус"
    - **Нужно знать:** методы HTTP, статусы, JSON, запрос и ответ, REST.
    - **Часто в работе:** query-параметры, заголовки, Network, отмена запроса.
    - **Достаточно узнавать:** CORS, кэширование и идемпотентность на базовом уровне.

## Запрос и ответ

```js
const response = await fetch("https://api.example.com/tasks?done=false", {
  headers: {
    Accept: "application/json",
  },
});

if (!response.ok) {
  throw new Error(`HTTP ${response.status}`);
}

const tasks = await response.json();
```

Запрос содержит метод, URL, заголовки и иногда тело. Ответ содержит статус, заголовки и тело. `response.json()` асинхронно читает тело и разбирает JSON.

## Основные методы

| Метод | Намерение | Обычно есть тело |
|---|---|---|
| GET | Получить ресурс | Нет |
| POST | Создать ресурс или запустить операцию | Да |
| PUT | Полностью заменить ресурс | Да |
| PATCH | Частично изменить ресурс | Да |
| DELETE | Удалить ресурс | Необязательно |

```js
await fetch("https://api.example.com/tasks", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ title: "Повторить Fetch" }),
});
```

`Content-Type` описывает формат отправленного тела. `Accept` сообщает желаемый формат ответа.

## Статусы

- `2xx`: успешная обработка;
- `3xx`: перенаправление;
- `4xx`: проблема запроса клиента;
- `5xx`: ошибка сервера.

Частые примеры: `200 OK`, `201 Created`, `204 No Content`, `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `500 Internal Server Error`.

У ответа `204` нет тела, поэтому не вызывайте для него `response.json()` без проверки.

## REST как модель ресурсов

```text
GET    /tasks       получить список
GET    /tasks/42    получить одну задачу
POST   /tasks       создать задачу
PATCH  /tasks/42    обновить часть задачи
DELETE /tasks/42    удалить задачу
```

REST связывает адреса с ресурсами, а методы HTTP с операциями. Это архитектурный стиль, а не отдельный протокол.

## Query и path-параметры

`/tasks/42` указывает конкретный ресурс. `/tasks?done=false&limit=10` фильтрует или настраивает представление списка.

```js
const params = new URLSearchParams({ done: "false", limit: "10" });
const response = await fetch(`/tasks?${params}`);
```

## Network и CORS

Во вкладке Network проверяйте URL, метод, status, request payload, response и timing. Если запрос виден, но JavaScript не получает ответ, посмотрите Console и заголовки CORS.

CORS является браузерным механизмом, который ограничивает чтение ответа с другого origin. Разрешение настраивает сервер. Добавление случайного заголовка на клиенте проблему не исправляет.

## Отмена запроса

```js
const controller = new AbortController();

fetch(url, { signal: controller.signal });
controller.abort();
```

Отмена полезна, если пользователь изменил поиск или ушел с экрана и старый результат больше не нужен.

!!! warning "Ловушка: 404 не отклоняет Fetch"
    Promise Fetch отклоняется при сетевой ошибке или отмене. Полученный HTTP-ответ 404 или 500 нужно проверить через `response.ok`.

## Как ответить на интервью

> HTTP использует запросы и ответы. Метод описывает намерение, URL ресурс, заголовки метаданные, тело данные, статус результат. REST обычно моделирует сущности адресами и применяет методы GET, POST, PATCH и DELETE. В Fetch отдельно проверяю `response.ok` и смотрю детали во вкладке Network.

## Мини-практика

На тестовом API получите список задач, создайте новую и измените ее. Для каждого запроса запишите метод, URL, статус, заголовок Content-Type и тело. Добавьте обработку 404 и отмену повторного поиска.
