# Производительность

<p class="reading-time">Чтение: 11 минут</p>

Сначала измерьте, затем оптимизируйте. Lighthouse показывает лабораторный снимок, Chrome DevTools и React Profiler помогают найти конкретную причину.

## Метрики пользователя

- **LCP**: когда появился главный контент;
- **INP**: насколько быстро интерфейс отвечает на действие;
- **CLS**: насколько сильно прыгает макет;
- **FCP**: когда пользователь увидел первый контент.

## Загрузка

- используйте подходящий формат и размер изображения;
- задавайте `width` и `height`, чтобы резервировать место;
- лениво загружайте контент ниже первого экрана;
- разделяйте код по маршрутам;
- удаляйте неиспользуемые зависимости;
- кешируйте статические ресурсы с хешем в имени.

```jsx
const AdminPage = lazy(() => import("./AdminPage"));

<Suspense fallback={<AdminPageSkeleton />}>
  <AdminPage />
</Suspense>
```

## Рендер React

Компонент рендерится, когда меняется его state, props или прочитанный context, либо рендерится родитель. Рендер не равен изменению DOM.

- `React.memo` пропускает рендер при равных props;
- `useMemo` кеширует вычисленное значение;
- `useCallback` кеширует функцию;
- виртуализация показывает только видимую часть длинного списка.

Мемоизация имеет стоимость и усложняет код. Применяйте ее после профилирования.

## Сеть и кеш

Избегайте водопадов запросов, объединяйте независимые запросы через `Promise.all`, задавайте политику устаревания кеша и не скачивайте лишние поля.

## Быстрый аудит

1. Запустите production build.
2. Проверьте Network: размер, число запросов, кеш.
3. Найдите LCP-элемент.
4. Запишите пользовательское действие в Performance.
5. Проверьте лишние рендеры в React Profiler.
6. Исправьте самый большой измеренный узкий участок.

!!! warning "Частая ошибка"
    Оценка только по быстрому компьютеру и локальному серверу скрывает проблемы сети и слабых устройств. Проверяйте throttling.
