# Интервью: PHP, SQL и Laravel

<p class="reading-time">20 ключевых вопросов с короткими ответами</p>

??? question "Где выполняется PHP?"
    На сервере. Веб-сервер передает запрос PHP-приложению, оно выполняет код и возвращает HTTP-ответ. Браузер получает результат, а не исходный PHP.

??? question "GET и POST?"
    GET получает представление ресурса и должен быть безопасным и идемпотентным. POST отправляет данные для создания или команды и не обязан быть идемпотентным.

??? question "Сессия и cookie?"
    Cookie хранится в браузере и отправляется серверу. Сессия обычно хранится на сервере, а cookie содержит ее идентификатор.

??? question "Как хранить пароль?"
    Через адаптивный password hash (`password_hash` / `password_verify`) с солью, а не в открытом виде и не обратимым шифрованием.

??? question "Как PDO защищает от SQL injection?"
    Подготовленный запрос передает структуру SQL и значения отдельно. Пользовательское значение не интерпретируется как часть команды.

??? question "PRIMARY KEY и FOREIGN KEY?"
    Первичный ключ уникально идентифицирует строку. Внешний ключ требует, чтобы связанное значение существовало в другой таблице, и поддерживает ссылочную целостность.

??? question "INNER JOIN и LEFT JOIN?"
    INNER оставляет только совпадения. LEFT сохраняет каждую строку левой таблицы и подставляет NULL, если совпадения справа нет.

??? question "WHERE и HAVING?"
    WHERE фильтрует строки до группировки, HAVING фильтрует группы после `GROUP BY`.

??? question "Зачем индекс?"
    Он ускоряет поиск, соединение и сортировку ценой места и более дорогой записи. Полезность проверяют реальным запросом и `EXPLAIN`.

??? question "Что гарантирует транзакция?"
    Набор изменений фиксируется как единое целое или откатывается. Это защищает инварианты при частичном сбое и конкурентной работе.

??? question "MVC?"
    Model отвечает за данные и правила, View за представление, Controller связывает HTTP-запрос со сценарием. В большом приложении бизнес-логику часто выносят в сервисы.

??? question "Что такое Eloquent ORM?"
    Он сопоставляет модели с таблицами, дает query builder и отношения. Удобство не отменяет понимания SQL, индексов и проблемы N+1.

??? question "Middleware в Laravel?"
    Код вокруг запроса, который проверяет или дополняет его: аутентификация, rate limit, CORS. Затем он передает запрос дальше или возвращает ответ.

??? question "Аутентификация и авторизация?"
    Аутентификация устанавливает личность. Авторизация проверяет разрешение на конкретное действие и объект.

??? question "Что делают Composer и PSR-4?"
    Composer управляет PHP-зависимостями и генерирует автозагрузчик. PSR-4 сопоставляет namespace класса с путем, поэтому приложение не подключает каждый файл ручным `require`.

??? question "Как разделить JSON endpoint?"
    Router выбирает controller, controller преобразует HTTP в вызов сценария, service применяет правило, repository работает с данными. Ответ содержит согласованный статус и JSON, а внутренняя ошибка записывается в лог.

??? question "Что такое подзапрос?"
    Это запрос, результат которого использует внешний запрос. Иногда ту же задачу яснее решает JOIN или CTE. Выбор проверяют читаемостью и планом выполнения.

??? question "Как избежать N+1 в Eloquent?"
    Заранее загрузить нужные отношения через eager loading, например `with`, и проверить число запросов. Один запрос списка и отдельный запрос для каждого элемента являются типичным признаком N+1.

??? question "Form Request и Policy решают одну задачу?"
    Form Request проверяет форму и может выполнить общую авторизацию запроса. Policy отвечает, разрешено ли конкретному пользователю действие над моделью. Проверка данных не заменяет проверку прав.

??? question "Что проверить при загрузке файла?"
    Размер, MIME-тип, расширение, безопасное имя, права доступа и место хранения. Нельзя доверять исходному имени или размещать любой загруженный файл как исполняемый публичный ресурс.
