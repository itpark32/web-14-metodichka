# Пробное full-stack интервью

<p class="reading-time">60 минут: теория, код и разбор проекта</p>

Попросите одногруппника выбрать вопросы случайно и задавать уточнение «почему?». Методичку открывайте только после блока.

## Web Core, 6 минут

1. Что происходит от ввода URL до отображения страницы?
2. Как браузер вычисляет итоговый CSS?
3. Чем кнопка отличается от ссылки?
4. Как проверить страницу с клавиатуры и скринридером?

## JavaScript, 8 минут

1. Сравните примитив и объект при копировании.
2. Объясните замыкание и практический пример.
3. Как определяется `this`?
4. В каком порядке выполняются Promise callback и `setTimeout`?
5. Почему `fetch` с `404` не попадает в `catch`?

## React и TypeScript, 10 минут

1. Что вызывает рендер компонента?
2. Когда `useEffect` не нужен?
3. Зачем React нужен `key`?
4. Сравните local state, Context, Redux и React Query.
5. Сравните `unknown`, `any` и `never`.
6. Как union помогает моделировать состояние запроса?

## Backend, 8 минут

1. Чем аутентификация отличается от авторизации?
2. Как подготовленный запрос защищает от SQL injection?
3. Сравните `INNER JOIN` и `LEFT JOIN`.
4. Зачем нужна транзакция?
5. Как проходит запрос через Laravel-приложение?

## Качество и проект, 8 минут

1. Какой сценарий проверить unit, integration и E2E-тестом?
2. Как доказать пользу `React.memo` через Profiler?
3. Что проверить в Network и Lighthouse перед публикацией?
4. Как вы перенесли макет из Figma и проверили Pixel Perfect?
5. Покажите один атомарный коммит и объясните решение из проекта.

```ts
type Order = {
  id: string;
  amount: number;
  status: "new" | "paid" | "cancelled";
};

function summarizeOrders(orders: Order[]) {
  // вернуть { revenue, paidCount }

```

Уточнения: пустой массив, отрицательная сумма, неизменность входа, сложность, тесты и вариант SQL-запроса.

## Проект, 8 минут

Выберите `Desserts`, `GitHub User Finder` или выпускной проект:

1. пользовательская задача;
2. архитектура и поток данных;
3. обработка загрузки и ошибок;
4. безопасность и тесты;
5. измеренная проблема производительности;
6. следующий шаг и его цена.

## Самооценка

| Уровень | Признак |
|---|---|
| Нужна доработка | определение появляется только после подсказки |
| База | определение и пример верны |
| Уверенно | есть механизм и частая ошибка |
| Сильно | есть ограничения, альтернатива и аргумент выбора |

После прогона записывайте конкретный пробел: не «плохо знаю React», а «не могу объяснить cleanup эффекта».
