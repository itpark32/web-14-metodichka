# Интервью: React

<p class="reading-time">16 ключевых вопросов с короткими ответами</p>

??? question "Что вызывает рендер React-компонента?"
    Изменение собственного state, новые props, изменение прочитанного context или рендер родителя. После вызова функции компонента React сравнивает новое дерево с предыдущим и применяет минимальные изменения к DOM.

??? question "Чем props отличаются от state?"
    Props приходят от родителя и только читаются. State принадлежит компоненту и изменяется setter или dispatch. Оба участвуют в формировании UI.

??? question "Зачем нужен `key`?"
    Он дает элементу стабильную идентичность среди соседей. React понимает, какой элемент добавлен, удален или перемещен, и не переносит локальное состояние на другую строку.

??? question "Почему state нельзя мутировать?"
    React ожидает новую ссылку, чтобы заметить изменение, а неизменяемые обновления сохраняют предыдущие снимки состояния и делают переходы предсказуемыми.

??? question "Когда нужен `useEffect`?"
    Для синхронизации с внешней системой: сетью, таймером, подпиской или не-React API. Для вычисления данных из props/state и обработки пользовательского действия эффект обычно не нужен.

??? question "Как работает массив зависимостей эффекта?"
    React сравнивает каждую зависимость через `Object.is`. После изменения запускает cleanup предыдущего эффекта, затем новый эффект. Пустой массив означает отсутствие реактивных зависимостей, а не «запустить один раз любой код».

??? question "Что делает cleanup?"
    Отписывается, очищает таймер, отменяет запрос или освобождает внешний ресурс перед повторным эффектом и размонтированием.

??? question "`useMemo` и `useCallback`?"
    `useMemo` кеширует результат вычисления, `useCallback` ссылку на функцию. Они полезны при измеренной стоимости или стабильности props мемоизированного потомка, но сами тоже имеют цену.

??? question "Контролируемое и неконтролируемое поле?"
    Контролируемое получает `value` из React state и обновляет его через `onChange`. Неконтролируемое хранит значение в DOM и читается через `ref` или `FormData`.

??? question "Как реализовать защищенный маршрут?"
    Маршрут проверяет состояние пользователя и показывает экран ожидания, перенаправляет на вход или рендерит страницу. Это навигационная защита; сервер все равно проверяет права на API.

??? question "Что такое custom hook?"
    Функция с именем `use...`, которая компонует хуки и переиспользует логику. Каждый вызов получает собственное состояние.

??? question "Как обрабатывать ошибку рендера?"
    Error Boundary ловит ошибку потомка во время рендера и показывает fallback. Он не заменяет обработку ошибок в event handler и асинхронном коде.

??? question "Что такое reconciliation?"
    React сравнивает новое дерево элементов с предыдущим и определяет минимальные изменения интерфейса. Тип элемента и `key` влияют на сохранение идентичности и локального состояния.

??? question "Как жизненный цикл класса связан с эффектом?"
    `componentDidMount` выполняется после первого добавления, `componentDidUpdate` после обновления, `componentWillUnmount` перед удалением. Эффект функционального компонента объединяет синхронизацию и cleanup вокруг набора зависимостей, но не является построчной заменой каждого метода.

??? question "Где выполнять условный рендеринг?"
    Компонент может вернуть разные элементы через `if`, тернарный оператор или `&&`. Условие должно оставаться читаемым, а взаимоисключающие состояния лучше моделировать явно, чтобы не показать loading и error одновременно.

??? question "Что означает поднять состояние?"
    Перенести общий факт к ближайшему общему родителю и передать данные и обработчики потомкам. Это создает один источник истины. Поднимать все состояние к корню не нужно, иначе растут связность и число рендеров.
