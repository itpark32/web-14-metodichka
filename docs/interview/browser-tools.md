# Интервью: браузер, сеть и архитектура

<p class="reading-time">26 вопросов · механизм, пример и способ проверки</p>

Этот блок связывает работу браузера, хранение данных, HTTP, REST API, инструменты разработчика, ES-модули и устройство небольшого SPA.

??? question "1. Что происходит после ввода URL в адресную строку?"
    Браузер разбирает URL, находит IP-адрес домена через DNS, устанавливает соединение и отправляет HTTP-запрос. Получив HTML, он строит DOM, загружает связанные ресурсы, рассчитывает стили и раскладку, затем рисует страницу. Часть шагов выполняется параллельно и повторяется для ресурсов.

??? question "2. Чем клиент отличается от сервера?"
    Клиент инициирует запрос и показывает интерфейс, сервер принимает запрос, выполняет бизнес-логику и возвращает ответ. Один браузер может обращаться к нескольким серверам, а сервер одновременно обслуживает много клиентов.

??? question "3. Для чего нужен DNS?"
    DNS сопоставляет доменное имя с IP-адресом, по которому можно найти сервер. Результаты кэшируются, поэтому преобразование не обязательно выполняется заново при каждом запросе.

??? question "4. Из каких частей состоит URL?"
    Обычно это схема, хост, необязательный порт, путь, строка запроса и фрагмент. Например, в `https://site.test/products?page=2#sale` схема равна `https`, путь `/products`, параметр `page=2`, а фрагмент `sale` обрабатывается браузером.

??? question "5. Чем BOM отличается от DOM?"
    DOM представляет HTML-документ объектами и позволяет менять его узлы. BOM объединяет браузерное окружение вокруг документа: `window`, `location`, `history`, `navigator`, размеры окна и таймеры. Граница условна, но помогает разделить страницу и возможности браузера.

??? question "6. Для чего нужны location и history?"
    `location` читает и меняет текущий адрес. `history` перемещается по истории и позволяет менять URL через `pushState` и `replaceState` без полной перезагрузки. SPA слушает `popstate`, чтобы синхронизировать интерфейс с кнопками Назад и Вперед.

??? question "7. Чем localStorage отличается от sessionStorage?"
    Оба хранят строки для конкретного источника. `localStorage` сохраняется между закрытиями браузера, `sessionStorage` живет в рамках вкладки до завершения ее сессии. Оба API синхронные и не подходят большим объемам данных.

??? question "8. Как сохранить объект в Web Storage?"
    Перед записью его сериализуют через `JSON.stringify`, а после чтения разбирают через `JSON.parse`. Чтение может вернуть `null`, а разбор поврежденной строки может выбросить ошибку, поэтому код должен учитывать оба случая.

??? question "9. Почему токен или пароль опасно хранить в localStorage?"
    Любой JavaScript, выполняющийся на странице, может прочитать эти данные. При XSS злоумышленник получает тот же доступ. Пароли там не хранят, а стратегию хранения токена выбирают вместе с защитой приложения и сервера.

??? question "10. Из чего состоят HTTP-запрос и ответ?"
    В запросе есть метод, адрес, заголовки и иногда тело. В ответе есть статус, заголовки и иногда тело. Вкладка Network показывает эти части и время прохождения запроса.

??? question "11. Как обычно используют GET, POST, PATCH и DELETE?"
    `GET` читает ресурс, `POST` создает ресурс или запускает действие, `PATCH` частично обновляет, `DELETE` удаляет. Это семантика протокола и контракта API; сам метод не реализует безопасность или валидацию.

??? question "12. Что означают группы HTTP-статусов?"
    `2xx` сообщает об успехе, `3xx` о перенаправлении, `4xx` об ошибке запроса клиента, `5xx` об ошибке на стороне сервера. Конкретный код дает больше смысла: например, 201 означает создание, 404 отсутствие ресурса.

??? question "13. Почему fetch не выбрасывает ошибку на 404?"
    Запрос технически получил HTTP-ответ, поэтому Promise выполняется успешно. Нужно проверить `response.ok` или `response.status` и самостоятельно выбросить ошибку для неуспешного статуса.

??? question "14. Что называют REST API?"
    Это стиль построения интерфейса вокруг ресурсов и стандартной семантики HTTP. Адрес обычно называет ресурс, метод выражает действие, запрос самодостаточен, а сервер возвращает представление и статус. Не всякое JSON API автоматически является REST.

??? question "15. Чем параметр пути отличается от query-параметра?"
    Параметр пути обычно идентифицирует ресурс, например `/users/42`. Query-параметры уточняют выборку, сортировку или страницу, например `/users?role=student&page=2`. Точное значение определяет контракт API.

??? question "16. Что такое CORS?"
    Это механизм HTTP-заголовков, через который сервер сообщает браузеру, каким другим источникам разрешен доступ к ответу. Ограничение применяет браузер. Исправить отсутствие разрешения только изменением клиентского `fetch` нельзя.

??? question "17. Как расследовать неработающий запрос во вкладке Network?"
    Проверить, ушел ли запрос, верны ли URL и метод, какой статус пришел, что находится в request payload, response и headers, был ли preflight. Затем сопоставить это с ошибкой в Console и контрактом API.

??? question "18. Как работают import и export?"
    Модуль явно экспортирует доступные значения, а другой модуль импортирует их по пути. Модули имеют собственную область видимости, выполняются один раз и позволяют браузеру построить граф зависимостей. В HTML точку входа подключают через `type="module"`.

??? question "19. Что такое SPA и какую проблему создает маршрутизация?"
    SPA меняет представление на клиенте без полной загрузки нового HTML при каждом переходе. При прямом открытии вложенного URL сервер все равно должен вернуть точку входа приложения, иначе пользователь получит 404. История браузера и интерфейс должны оставаться синхронизированы.

??? question "20. Наследование или композиция: что выбрать?"
    Наследование удобно для настоящего отношения «является», но создает сильную связь с базовым классом. Композиция собирает объект из небольших независимых возможностей и обычно легче меняется. Выбор объясняют моделью предметной области, а не желанием обязательно использовать класс.

??? question "21. Что проверить в Figma до начала верстки?"
    Размер и сетку фрейма, ширину контейнера, отступы, типографику, цвета, состояния компонентов и поведение Auto Layout. Также нужно понять, какие изображения и SVG экспортировать, а какие эффекты собрать средствами CSS.

??? question "22. Что означает Pixel Perfect на практике?"
    Это системная проверка соответствия макету при одинаковом размере viewport, а не ручная подгонка каждого пикселя. Сначала сравнивают контейнер, сетку, типографику и крупные интервалы, затем состояния и детали. Наложение или скриншот помогает найти повторяющуюся причину расхождений.

??? question "23. Чем рабочая директория, stage и commit отличаются в Git?"
    В рабочей директории находятся текущие изменения файлов. `git add` помещает выбранную версию изменения в stage, а `git commit` сохраняет снимок stage в истории. Изменение после `git add` может одновременно иметь staged и unstaged части.

??? question "24. Зачем нужна ветка и что такое конфликт слияния?"
    Ветка является перемещаемым указателем на цепочку коммитов и позволяет развивать изменение отдельно. Конфликт возникает, когда Git не может автоматически совместить конкурирующие изменения. Разработчик выбирает итоговое содержимое, проверяет его и завершает слияние коммитом.

??? question "25. Что делает Webpack?"
    Он начинает с точек входа, строит граф импортов и создает один или несколько итоговых ресурсов. Loaders преобразуют типы модулей, plugins участвуют в более широких этапах сборки. Webpack не заменяет понимание браузерных ES-модулей.

??? question "26. Зачем нужны dev server и source map?"
    Dev server ускоряет локальную разработку, пересобирает проект и обновляет страницу при изменениях. Source map связывает собранный код с исходными файлами, чтобы отладчик показывал знакомые строки. Эти инструменты помогают разработке, но не исправляют ошибку приложения автоматически.
