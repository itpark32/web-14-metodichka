# 14. Git и GitHub

<p class="reading-time">Чтение: 6 минут</p>

Git хранит историю проекта локально. GitHub размещает удаленный репозиторий и помогает работать вместе через ветки, Pull Request и Code Review.

!!! abstract "Фокус"
    - **Нужно знать:** `status`, `add`, `commit`, `pull`, `push`, ветки и конфликты.
    - **Часто в работе:** `.gitignore`, осмысленные коммиты, чтение diff.
    - **Достаточно узнавать:** сложные стратегии слияния и переписывание истории.

## Обычный цикл

```bash
git status
git add index.html style.css
git commit -m "Add responsive navigation"
git push origin main
```

`git status` показывает состояние. `git add` готовит выбранные изменения, `commit` фиксирует снимок, `push` отправляет коммиты в удаленный репозиторий.

## Ветка для задачи

```bash
git switch -c feature/mobile-menu
# изменения и проверка
git add .
git commit -m "Add mobile menu"
git push -u origin feature/mobile-menu
```

После этого создают Pull Request. Хороший PR решает одну задачу, имеет понятное описание и не содержит случайных файлов.

## Конфликт

Конфликт возникает, когда Git не может автоматически объединить изменения. В файле появляются маркеры:

```text
<<<<<<< HEAD
текущая версия
=======
версия из другой ветки
>>>>>>> feature
```

Выберите правильный итоговый текст, удалите маркеры, проверьте проект и создайте коммит.

!!! danger "Секреты не попадают в Git"
    Пароли, токены и ключи API нельзя коммитить. Добавьте локальные файлы с секретами в `.gitignore`. Удаление секрета новым коммитом не стирает его из старой истории.

## Где это было

В репозитории [test-github-2025](https://github.com/likermusic/test-github-2025) поток работал с ветками, слияниями, Pull Request и конфликтами.

## Как ответить на интервью

> Git хранит историю снимков проекта. Рабочие изменения добавляю в индекс через `git add`, фиксирую `git commit`, получаю удаленные изменения через `pull` и отправляю свои через `push`. Перед объединением веток проверяю статус и разрешаю конфликты осознанно.

## Мини-практика

Создайте ветку `feature/readme`, добавьте описание проекта, сделайте один осмысленный коммит и откройте Pull Request.
