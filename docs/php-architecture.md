# 45. PHP: архитектура, Composer и API

<p class="reading-time">Чтение: 10 минут</p>

Когда PHP-приложение растет, его нужно разделить на HTTP-слой, бизнес-правила и работу с данными, а зависимости подключать предсказуемо.

!!! abstract "Фокус"
    - **Нужно знать:** MVC, namespace, автозагрузка, Composer, JSON API и AJAX.
    - **Часто в работе:** роутинг, человекочитаемые URL, консольные команды и внешние API.
    - **Достаточно узнавать:** ручной парсинг HTML и сложные правила веб-сервера.

## MVC без магии

```text
HTTP request -> Router -> Controller -> Service -> Repository -> Database
                                      -> View or JSON response
```

Controller преобразует HTTP-запрос в вызов сценария. Service хранит бизнес-правило, repository изолирует работу с данными, view формирует HTML. MVC не означает, что вся логика должна жить в контроллере или модели.

## Namespace, автозагрузка и Composer

```php
namespace App\Catalog;

final class ProductService {}
```

Composer устанавливает пакеты и по правилу PSR-4 сопоставляет namespace с каталогом. После `composer install` приложение подключает `vendor/autoload.php`, поэтому классы не требуют цепочки ручных `require`.

## URL и веб-сервер

Человекочитаемый адрес `/products/42` направляется в одну точку входа, а router выбирает обработчик. Apache может выполнять это через `.htaccess`, Nginx через свою конфигурацию. Правило не должно открывать служебные файлы или позволять составлять произвольный путь.

## JSON API и AJAX

AJAX означает запрос из уже открытой страницы без полной перезагрузки. Современный код обычно использует Fetch и JSON.

```php
header('Content-Type: application/json; charset=utf-8');

echo json_encode([
    'data' => $products,
], JSON_UNESCAPED_UNICODE);
```

API возвращает согласованные статусы и структуру ошибок. PHP может обращаться к внешнему API через HTTP-клиент, но должен обрабатывать timeout, неверный статус и поврежденный ответ.

## Парсинг и фоновые задачи

Парсер сначала проверяет разрешение на получение данных, затем ограничивает частоту запросов и устойчиво работает с изменением структуры источника. Долгую операцию удобнее запускать консольной командой или очередью, а не удерживать пользовательский HTTP-запрос.

!!! warning "Ловушка: тонкий router, толстый controller"
    Перенос всей логики из одного файла в controller не создает архитектуру. Разделение полезно, когда части имеют разные причины для изменения и их можно проверять отдельно.

## Как ответить на интервью

> MVC разделяет HTTP-координацию, правила, данные и представление. Composer управляет пакетами и автозагрузкой PSR-4, namespace устраняет конфликты имен. Для AJAX-запроса PHP возвращает JSON, корректный HTTP-статус и предсказуемую структуру ошибки.

## Мини-практика

Разделите endpoint каталога на router, controller, service и repository. Настройте PSR-4, верните JSON для Fetch и добавьте обработку неизвестного маршрута, неверных данных и сбоя внешнего API.
