# 5. Доступность веб-интерфейсов

<p class="reading-time">Чтение: 9 минут</p>

> **Подтверждено проектами:** в уроке 12 разобраны семантические роли, `label`, `tabindex`, `aria-label`, `aria-labelledby`, `aria-describedby` и скрытие от скринридера.

Доступность означает, что интерфейс можно понять и использовать с клавиатурой, скринридером, увеличением и при разных особенностях восприятия.

!!! abstract "Фокус"
    - **Нужно знать:** нативная семантика, доступное имя, клавиатура и фокус.
    - **Часто в работе:** `aria-*`, сообщения об ошибках и ручная проверка сценария.
    - **Достаточно узнавать:** сложные ARIA-паттерны, пока их не требует интерфейс.

## Сначала нативный HTML

Кнопка выполняет действие, ссылка переводит по адресу, `label` подписывает поле. Нативный элемент уже содержит семантику и клавиатурное поведение.

```html
<label for="email">Почта</label>
<input id="email" name="email" type="email" autocomplete="email" required>
<button type="submit">Отправить</button>
```

`<div role="button">` требует вручную реализовать фокус, Enter, Space и disabled-состояние. Обычно он не нужен.

## Доступное имя

Элементу управления нужно имя, которое сообщает назначение:

1. видимый текст;
2. связанный `<label>`;
3. `aria-labelledby`;
4. `aria-label`, если видимой подписи действительно нет.

`placeholder` не заменяет `label`: он исчезает при вводе и часто имеет слабый контраст.

## Клавиатура и фокус

- порядок Tab должен совпадать с визуальным порядком;
- фокус должен быть заметен;
- `tabindex="0"` добавляет элемент в естественный порядок;
- `tabindex="-1"` позволяет сфокусировать элемент программно;
- положительные значения `tabindex` почти всегда создают путаницу;
- модальное окно удерживает фокус внутри и возвращает его кнопке открытия.

## ARIA без лишней магии

ARIA дополняет семантику, но не меняет поведение элемента.

```html
<button aria-expanded="false" aria-controls="catalog-menu">
  Каталог
</button>
<nav id="catalog-menu" hidden>...</nav>
```

При открытии нужно синхронно изменить `hidden` и `aria-expanded`.

## Быстрая проверка

1. Пройдите страницу только клавиатурой.
2. Увеличьте масштаб до 200%.
3. Проверьте структуру заголовков и landmarks.
4. Запустите Lighthouse или axe.
5. Проверьте контраст и сообщения об ошибках.
6. Убедитесь, что смысл не передается только цветом.

!!! warning "Частая ошибка"
    ARIA не исправляет неверный HTML. Правило «No ARIA is better than bad ARIA» напоминает: сначала выберите правильный нативный элемент.

## Как ответить на интервью

> Доступный интерфейс сохраняет смысл и управление без мыши. Я начинаю с нативных элементов, связываю поля с подписями, делаю фокус видимым и использую ARIA только для недостающей семантики. Затем прохожу ключевой сценарий клавиатурой и проверяю доступное имя.

## Мини-задача

Сделайте раскрывающееся меню, которое работает мышью и клавиатурой, закрывается по Escape, обновляет `aria-expanded` и возвращает фокус кнопке.
