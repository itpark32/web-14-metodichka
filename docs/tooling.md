# Vite, сборка проекта и качество кода

<p class="reading-time">Чтение и разбор примеров: 10–15 минут</p>

Сборка превращает исходные модули и ресурсы в файлы для публикации. Для нового небольшого frontend-проекта основной путь — Node.js, npm и Vite. Webpack важно уметь читать в существующем проекте.

!!! abstract "Фокус"
    - **Нужно знать:** Node.js, npm, package.json, dev server, build и dist.
    - **Часто в работе:** lock-файл, scripts, ESLint, Prettier и source maps.
    - **Достаточно узнавать:** сложные loaders/plugins и дополнительные Git hooks.

## От Node.js до браузера

```text
Node.js → npm → package.json → Vite → dev server
                                     ↓ npm run build
                                    dist → hosting
```

Node.js выполняет JavaScript вне браузера: запускает сборщик, линтер и тесты. Это не означает, что браузерное приложение получает доступ к файловой системе Node.js. npm устанавливает пакеты и запускает команды проекта.

## Минимальный проект

Установите поддерживаемую текущим Vite версию Node.js, затем выполните:

```bash
npm create vite@latest catalog -- --template react
cd catalog
npm install
npm run dev
```

Первая команда создает каталог `catalog` из шаблона React. `npm install` читает manifest и устанавливает зависимости в `node_modules`. `npm run dev` запускает локальный сервер и выводит адрес в терминале. Откройте его, измените текст компонента и проверьте обновление страницы.

Vite использует ES-модули для разработки. HMR (Hot Module Replacement) обновляет измененные модули без полной перезагрузки там, где это возможно, что ускоряет обратную связь.

## Что находится в package.json

Ниже показан раздел `scripts` внутри созданного manifest, а не замена всего файла:

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview",
    "lint": "eslint ."
  }
}
```

`npm run build` запускает строку из `scripts.build`. npm находит локальный исполняемый файл установленного Vite, поэтому членам команды не нужно устанавливать сборщик глобально.

| Поле или файл | Зачем нужен |
|---|---|
| `dependencies` | Пакеты приложения, например React |
| `devDependencies` | Инструменты разработки и сборки, например Vite, ESLint |
| `scripts` | Единые команды запуска, проверок и сборки |
| `package-lock.json` | Точное дерево установленных версий |
| `node_modules/` | Локальная установленная копия пакетов |

Установка runtime-пакета: `npm install react`. Установка инструмента: `npm install -D prettier`. Обе команды обновляют manifest и lock-файл. Для frontend даже `devDependencies` нужны на машине, которая собирает production: их название не означает «можно пропустить при сборке».

`package.json` может разрешать диапазоны версий; lock-файл делает установку воспроизводимой. Храните оба в Git. `node_modules` и `dist` обычно добавляют в `.gitignore`: их можно восстановить. Для чистой установки в CI используйте `npm ci`, который требует согласованный lock-файл и не переписывает его.

## Dev server и production build

```bash
npm run lint
npm run build
npm run preview
```

Development-сервер оптимизирован для скорости изменений и диагностики. Production build оптимизирует ресурсы для доставки пользователю и обычно создает каталог `dist`. В статическом Vite-проекте это HTML, JavaScript, CSS и другие ресурсы.

`preview` помогает локально проверить собранный `dist`. Он не является командой промышленного размещения. Для публикации загрузите результат на статический хостинг или настройте сервер. У SPA сервер должен возвращать `index.html` для клиентских маршрутов, иначе прямое открытие `/products/42` даст 404. При публикации в подкаталоге настройте `base` и проверьте пути к ресурсам.

## Webpack: как читать конфигурацию

```js
export default {
  mode: "production",
  entry: "./src/index.js",
  output: { filename: "bundle.js", clean: true },
  module: {
    rules: [
      { test: /\.css$/i, use: ["style-loader", "css-loader"] },
    ],
  },
};
```

Это фрагмент конфигурации существующего Webpack-проекта с установленными loaders. `entry` задает входной модуль, `output` — результат. Webpack обходит импорты и строит граф зависимостей. В примере CSS обрабатывается `css-loader`, а `style-loader` вставляет стили в страницу. Plugins выполняют более общие действия, например формируют HTML или извлекают CSS в файл.

Webpack распространен в существующих и крупных проектах. Для обучения достаточно понимать граф, режимы и базовую конфигурацию; глубокая настройка loaders/plugins не нужна для первого приложения. CRA (Create React App) тоже встречается в старом коде: сначала прочитайте его scripts, затем решайте, нужна ли миграция.

## Проверки и отладка

Prettier форматирует код. ESLint ищет вероятные ошибки и нарушения правил; например, плагины React помогают проверить зависимости эффектов. Их задачи дополняют друг друга. Добавляйте правила и конфигурацию вместе с пакетами: одна установка ESLint не создает правила проекта.

Source maps связывают собранный код с исходниками, чтобы DevTools показывал знакомые строки. Husky может запускать проверки перед Git-операциями; это дополнительное удобство, а обязательные проверки должны выполняться и в CI.

## Публикация и окружение

```text
source → npm ci → lint / tests → build → dist → hosting / server
```

Разделяйте development и production-настройки. В Vite публичные значения обычно читают через `import.meta.env.VITE_API_URL`. Значение, попавшее в browser bundle, пользователь может увидеть. Пароли, приватные ключи и серверные токены нельзя хранить во frontend-коде или переменных с префиксом `VITE_`. Серверные секреты остаются на сервере.

## Частые ошибки

- Запускать команды вне каталога с `package.json`: npm не найдет scripts.
- Удалять lock-файл при каждом сбое: это меняет версии вместо устранения причины.
- Публиковать исходники вместо `dist` или забывать проверить production build.
- Считать dev server и production-сервер одной средой: пути и переменные могут отличаться.

## Как ответить на интервью

> Node.js запускает инструменты, npm устанавливает пакеты и выполняет scripts. Vite предоставляет dev server с HMR и production build. Manifest описывает проект, lock-файл фиксирует версии, а результат сборки размещают на хостинге. ESLint проверяет код, Prettier форматирует.

## Мини-практика

Создайте Vite-проект каталога, найдите scripts и обе группы зависимостей. Измените компонент, выполните lint и build, откройте preview. Объясните, какие файлы попадут в Git и какие — на хостинг.
