# 39. Тестирование веб-приложений

<p class="reading-time">Чтение: 13 минут</p>

Тест фиксирует ожидаемое поведение. Хороший набор дает уверенность при изменениях, а не пытается проверить каждую строку.

!!! abstract "Фокус"
    - **Нужно знать:** unit, integration, E2E, AAA и поведение пользователя.
    - **Часто в работе:** Jest, React Testing Library, mocks, async queries и user events.
    - **Достаточно узнавать:** внутреннее устройство test runner и редкие matcher-функции.

## Уровни

- **статические проверки**: TypeScript, ESLint;
- **unit**: чистая функция или небольшой модуль;
- **интеграционные**: несколько частей работают вместе;
- **component**: компонент глазами пользователя;
- **end-to-end**: критический сценарий в реальном браузере.

Чем выше уровень, тем реалистичнее и дороже тест.

## Arrange, Act, Assert

```js
it("считает сумму корзины", () => {
  const items = [
    { price: 120, quantity: 2 },
    { price: 80, quantity: 1 },
  ];

  const result = calculateTotal(items);

  expect(result).toBe(320);
});
```

## React Testing Library

```jsx
render(<LoginForm onSubmit={submit} />);

await user.type(screen.getByLabelText(/почта/i), "student@example.com");
await user.click(screen.getByRole("button", { name: /войти/i }));

expect(submit).toHaveBeenCalledWith({ email: "student@example.com" });
```

Ищите элементы по роли и доступному имени. Это ближе к реальному использованию и одновременно проверяет доступность.

## Моки

Mock проверяет взаимодействие, stub возвращает подготовленный результат, spy наблюдает за вызовом. Мокайте границу системы, например сеть, время или файловую систему. Не мокайте внутренности компонента без причины.

Для HTTP удобно использовать MSW: компонент делает настоящий `fetch`, а тест перехватывает запрос на уровне сети.

## Асинхронный тест

Проверяйте не только успех, но и загрузку, пустой ответ и ошибку. Используйте `findBy...` или `waitFor`, если UI изменяется позже.

!!! warning "Частая ошибка"
    Тест, который проверяет внутренний state или имя метода, ломается при безопасном рефакторинге. Проверяйте наблюдаемое поведение пользователя.

## Как ответить на интервью

> Unit-тест проверяет небольшую единицу, интеграционный тест взаимодействие частей, E2E критический путь в браузере. В React Testing Library я ищу элементы так, как их воспринимает пользователь, выполняю действие и проверяю видимый результат. Внешнюю границу можно подменить, но внутренние детали компонента лучше не мокать.
