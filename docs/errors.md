# 24. Ошибки и обработка исключений

<p class="reading-time">Чтение: 8 минут</p>

Исключение сообщает, что выполнение не может корректно продолжаться. Задача обработчика не скрыть ошибку, а восстановиться, показать понятное состояние или передать проблему выше.

!!! abstract "Фокус"
    - **Нужно знать:** `Error`, `throw`, `try`, `catch`, `finally`.
    - **Часто в работе:** собственное сообщение, повторный проброс, обработка ошибок API.
    - **Достаточно узнавать:** пользовательские классы ошибок и глобальные обработчики.

## Создание ошибки

```js
function divide(a, b) {
  if (b === 0) {
    throw new Error("Деление на ноль невозможно");
  }

  return a / b;
}
```

`throw` немедленно прерывает текущий путь выполнения. Обычно выбрасывают объект `Error`, потому что он хранит сообщение и стек вызовов.

## Перехват

```js
try {
  const settings = JSON.parse(rawSettings);
  applySettings(settings);
} catch (error) {
  console.error(error);
  showMessage("Настройки повреждены");
} finally {
  hideLoader();
}
```

- `try` содержит потенциально падающий код;
- `catch` получает ошибку;
- `finally` выполняется после успеха или ошибки.

Не окружайте весь проект одним большим `try/catch`. Обрабатывайте ошибку там, где понятно, как восстановиться или что показать пользователю.

## Не проглатывайте ошибку

```js
async function loadProfile() {
  try {
    return await requestProfile();
  } catch (error) {
    console.error("Profile request failed", error);
    throw error;
  }
}
```

Повторный `throw` передает ошибку вызывающему коду. Если `catch` ничего не возвращает и не выбрасывает, вызывающий код может ошибочно решить, что операция завершилась успешно со значением `undefined`.

## Ожидаемая ошибка и ошибка программы

Неверно заполненное поле является ожидаемым пользовательским состоянием. Его лучше показать рядом с полем, а не бросать исключение на каждую пустую строку.

Неожиданный формат ответа, недоступный сервер или нарушение внутреннего контракта могут обрабатываться как исключения.

!!! warning "Ловушка: catch исправляет все"
    `try/catch` перехватывает исключения в своем синхронном пути и ошибки ожидаемого Promise. Он не исправляет логическую ошибку, когда код отработал без исключения, но посчитал неверный результат.

## Как ответить на интервью

> `throw` создает исключительный путь, `catch` позволяет его обработать, `finally` выполняет очистку независимо от результата. Я перехватываю ошибку там, где могу восстановить интерфейс или добавить контекст. Не проглатываю исключение: либо возвращаю понятный результат, либо пробрасываю его дальше.

## Мини-практика

Напишите функцию чтения настроек из JSON. Для пустой строки верните настройки по умолчанию, для некорректного JSON покажите понятную ошибку, а в `finally` уберите состояние загрузки.
