# 6. CSS: каскад и блочная модель

<p class="reading-time">Чтение: 10 минут</p>

CSS выбирает элементы и рассчитывает их итоговый внешний вид. Когда стиль «не работает», причина чаще всего находится в селекторе, каскаде, размере элемента или потоке документа.

!!! abstract "Фокус"
    - **Нужно знать:** селекторы, каскад, наследование, специфичность, box model, `display`, `position`.
    - **Часто в работе:** псевдоклассы, псевдоэлементы, CSS-переменные, `overflow`.
    - **Достаточно узнавать:** старые раскладки на `float`, редкие глобальные ключевые слова.

## Из чего состоит CSS-правило

```css
.product-card {
  width: 20rem;
  padding: 1.5rem;
  border: 1px solid #d7dfdc;
  background-color: #f7faf8;
}

.product-card:hover {
  border-color: #174c43;
}
```

Селектор выбирает элементы, внутри фигурных скобок находятся объявления `свойство: значение`. Класс удобен для переиспользования. `id` лучше оставлять для якорей, связи `label` с полем и редких уникальных целей JavaScript.

## Селекторы, которые нужны постоянно

```css
button {}                    /* тег */
.card {}                     /* класс */
[data-state="open"] {}      /* атрибут */
.card > .card__title {}      /* прямой потомок */
.field:focus-visible {}      /* состояние */
.card::before {}             /* создаваемый фрагмент */
```

Псевдокласс выбирает существующий элемент в состоянии: `:hover`, `:focus-visible`, `:checked`, `:disabled`, `:first-child`. Псевдоэлемент обращается к части элемента или создает оформительский фрагмент: `::before`, `::after`, `::placeholder`.

## Как браузер выбирает победителя

Удобная практическая модель:

1. подходит ли правило к элементу;
2. есть ли особая важность, например `!important`;
3. какой селектор специфичнее;
4. при равном весе какое правило объявлено позже.

```css
p { color: #555; }          /* 0-0-1 */
.note { color: #174c43; }   /* 0-1-0 */
#intro { color: #c44b2b; }  /* 1-0-0 */
```

Числа полезны как модель: ID сильнее класса, класс сильнее тега. Но сначала браузер учитывает источник и важность. Инлайновый стиль и `!important` требуют отдельного внимания.

!!! warning "Ловушка: лечить каскад новым important"
    Если добавлять `!important` при каждом конфликте, следующий стиль потребует еще более сильного правила. Сначала откройте Styles и Computed в DevTools, найдите перечеркнутое объявление и выясните, почему оно проиграло.

## Наследование

Текстовые свойства, например `color` и `font-family`, часто наследуются. Размеры, фон, границы и отступы обычно нет.

```css
body {
  color: #17322c;
  font-family: system-ui, sans-serif;
}
```

Ключевое слово `inherit` заставляет взять значение у родителя. `initial` возвращает начальное значение свойства, `unset` ведет себя как `inherit` для наследуемого свойства и как `initial` для остальных.

## Блочная модель

Элемент состоит из `content`, `padding`, `border` и `margin`.

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

При `content-box` заданные `width` и `height` относятся только к содержимому. При `border-box` они включают `padding` и `border`.

Если элемент имеет `width: 300px`, `padding: 20px` и границу `2px`, его внешняя ширина при `content-box` равна `344px`. При `border-box` она остается `300px`.

`margin` отделяет элемент снаружи. Вертикальные отступы обычных блочных элементов иногда схлопываются. У flex- и grid-элементов такого схлопывания нет.

## `display` и поток

- `block` занимает доступную ширину и начинается с новой строки;
- `inline` участвует в строке, а ширина и высота применяются не как у блока;
- `inline-block` остается в строке, но принимает размеры;
- `none` убирает элемент из раскладки и дерева доступности;
- `flex` и `grid` создают отдельную модель раскладки для потомков.

## Позиционирование

| Значение | Место в потоке | Относительно чего смещается |
|---|---|---|
| `static` | Сохраняется | Смещение не применяется |
| `relative` | Сохраняется | Собственное обычное положение |
| `absolute` | Не сохраняется | Ближайший позиционированный предок |
| `fixed` | Не сохраняется | Область просмотра, с оговорками для трансформаций |
| `sticky` | Сохраняется | Контейнер прокрутки и заданный порог |

```css
.card { position: relative; }
.card__badge { position: absolute; top: 1rem; right: 1rem; }
```

Для `sticky` обычно нужен порог, например `top: 0`. Он может не сработать из-за `overflow` у предка или отсутствия пространства для прокрутки.

## Единицы и переменные

- `px` удобен для тонкой границы и точного небольшого размера;
- `rem` зависит от корневого размера шрифта и удобен для масштаба интерфейса;
- `%` зависит от контекста свойства;
- `vw`, `vh`, `dvh` зависят от области просмотра;
- `fr` делит свободное место в Grid.

```css
:root {
  --color-accent: #174c43;
  --space-card: clamp(1rem, 2vw, 1.5rem);
}

.card {
  padding: var(--space-card);
  color: var(--color-accent);
}
```

## Как ответить на интервью

> Итоговый CSS определяется каскадом: сначала применимость и важность, затем специфичность, затем порядок. Размер элемента рассчитывается по блочной модели. Я обычно включаю `border-box`, использую классы с невысокой специфичностью и проверяю проигравшие правила в DevTools вместо добавления `!important`.

## Мини-практика

Создайте две карточки шириной `300px`. Одной задайте `content-box`, второй `border-box`, обеим добавьте `padding: 20px` и `border: 2px solid`. Затем специально создайте конфликт трех селекторов и найдите победившее правило в DevTools.
