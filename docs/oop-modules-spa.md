# 31. ООП, ES-модули и архитектура SPA

<p class="reading-time">Чтение: 10 минут</p>

Эти темы отвечают за организацию приложения: как описать сущность, разделить код по файлам и менять экраны без полной перезагрузки документа.

!!! abstract "Фокус"
    - **Нужно знать:** объект, класс, экземпляр, `import`, `export`, принцип SPA.
    - **Часто в работе:** композиция, разделение ответственности, History API.
    - **Достаточно узнавать:** глубокие цепочки наследования и сложные архитектурные паттерны.

## Класс и экземпляр

```js
class Task {
  constructor(title) {
    this.title = title;
    this.done = false;
  }

  complete() {
    this.done = true;
  }
}

const task = new Task("Повторить модули");
task.complete();
```

Класс является шаблоном создания объектов. `constructor` инициализирует экземпляр, методы доступны через прототип. `this` у метода определяется способом вызова.

## Наследование и композиция

```js
class TimedTask extends Task {
  constructor(title, deadline) {
    super(title);
    this.deadline = deadline;
  }
}
```

`extends` связывает классы, `super` вызывает логику родителя. Наследование полезно для настоящего отношения «является», но длинные цепочки усложняют код. Часто проще собрать объект из небольших функций или зависимостей.

## Инкапсуляция

Объект должен защищать свои правила и предоставлять понятные операции. Необязательно превращать каждый объект данных в класс.

```js
class Counter {
  #value = 0;

  increment() {
    this.#value += 1;
  }

  get value() {
    return this.#value;
  }
}
```

Поле с `#` является приватным на уровне языка.

## ES-модули

```js
// math.js
export function sum(a, b) {
  return a + b;
}

// index.js
import { sum } from "./math.js";
console.log(sum(2, 3));
```

В браузере без сборщика точка входа подключается как модуль:

```html
<script type="module" src="./index.js"></script>
```

Модули имеют собственную область видимости, работают в строгом режиме и позволяют явно описать зависимости. Путь локального модуля должен начинаться с `./`, `../` или `/`.

## Роли файлов

Один из простых вариантов разделения:

```text
src/
  api.js       запросы и преобразование ответа
  storage.js   работа с хранилищем
  view.js      создание и обновление DOM
  state.js     данные приложения
  index.js     связывает части и запускает приложение
```

Названия отвечают ответственности. Если файл делает все сразу, его сложно тестировать и менять.

## Что такое SPA

Single Page Application загружает один основной HTML-документ, а затем JavaScript меняет содержимое и состояние маршрута без полной перезагрузки страницы.

```js
history.pushState({ page: "catalog" }, "", "/catalog");

window.addEventListener("popstate", () => {
  renderRoute(location.pathname);
});
```

Маршрут должен открываться напрямую и после обновления. Для этого сервер обычно возвращает основной HTML для клиентских маршрутов. SPA не означает один экран или отсутствие URL.

!!! warning "Ловушка: класс ради класса"
    ООП является способом организации, а не обязательной оболочкой для каждой функции. Используйте класс, когда нужны экземпляры с общим поведением и внутренними правилами.

## Как ответить на интервью

> Класс описывает создание экземпляров с общими методами, которые размещаются в прототипе. ES-модули дают собственную область видимости и явные зависимости через import и export. SPA меняет экран на клиенте без полной загрузки нового HTML, но должно сохранять URL, историю и прямое открытие маршрута.

## Мини-практика

Разделите список задач на `storage.js`, `view.js` и `index.js`. Добавьте класс только для сущности, у которой есть правило изменения состояния. Реализуйте два маршрута через History API и проверьте кнопку браузера «Назад».
