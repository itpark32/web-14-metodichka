# Команда и процессы разработки

<p class="reading-time">Чтение: 9 минут</p>

## Жизненный цикл функции

Проблема пользователя -> требования -> дизайн -> декомпозиция -> разработка -> code review -> тестирование -> релиз -> наблюдение и обратная связь.

## Роли

Product Manager отвечает за ценность и приоритет, дизайнер за пользовательский сценарий, разработчик за реализацию, QA за стратегию качества, DevOps/SRE за доставку и надежность. Ответственность может пересекаться, но решение должно иметь владельца.

## Agile, Scrum и Kanban

Agile описывает ценности адаптивной разработки. Scrum организует работу короткими спринтами, ролями и событиями. Kanban визуализирует поток и ограничивает незавершенную работу.

Не путайте ежедневную встречу с отчетом начальнику. Ее цель: синхронизировать план и обнаружить блокеры.

## Задача перед разработкой

Уточните пользовательскую ценность, критерии приемки, дизайн-состояния, контракт API, аналитику, риски доступности и способ проверки.

## Git-процесс

Создайте небольшую ветку, делайте атомарные коммиты, обновите тесты, откройте pull request с контекстом и способом проверки. На review обсуждают код, не человека.

## Как говорить о конфликте

1. Опишите наблюдаемый факт.
2. Объясните риск для задачи.
3. Предложите вариант и проверку.
4. Зафиксируйте решение команды.

## Мини-задача

Составьте pull request для добавления корзины в `Desserts`: цель, изменения, скриншоты состояний, тест-план, риски и шаги отката.
