# 44. PHP: серверная основа

<p class="reading-time">Чтение: 13 минут</p>

PHP выполняется на сервере. Он принимает HTTP-запрос, читает данные, применяет правила и формирует HTML или JSON-ответ.

!!! abstract "Фокус"
    - **Нужно знать:** переменные, условия, массивы, функции, формы, файлы и ошибки.
    - **Часто в работе:** HTTP, JSON, PDO, сессии, cookie, ООП и Composer.
    - **Достаточно узнавать:** тонкости конфигурации веб-сервера и собственного автозагрузчика.

## Базовый синтаксис

```php
<?php
$name = trim($_POST['name'] ?? '');

if ($name === '') {
    http_response_code(422);
    echo json_encode(['error' => 'Введите имя']);
    exit;
}

echo json_encode(['message' => "Привет, $name"]);
```

Переменная начинается с `$`. Массив может быть индексным или ассоциативным. `===` сравнивает и значение, и тип. Клиентскому вводу доверять нельзя.

## GET и POST

- `$_GET` читает параметры URL;
- `$_POST` читает данные формы;
- `$_FILES` содержит загрузки;
- `$_SERVER` содержит сведения о запросе;
- сырой JSON читают из `php://input`.

После изменения данных используйте redirect, чтобы обновление страницы не повторило POST.

## Файлы и ошибки

Проверяйте существование файла, права, размер и MIME-тип. Не составляйте путь напрямую из пользовательской строки. Исключения перехватываются `try/catch`, а детали ошибки пишутся в лог, не в публичный ответ.

## ООП

```php
final class CartService
{
    public function __construct(private ProductRepository $products) {}

    public function total(array $items): int
    {
        // business rules
    }
}
```

Интерфейс задает контракт, абстрактный класс может содержать общую реализацию, Composer устанавливает пакеты и настраивает автозагрузку PSR-4.

## Сессия и cookie

Сессия хранит данные на сервере, cookie обычно содержит идентификатор. Для cookie аутентификации нужны `HttpOnly`, `Secure` и подходящий `SameSite`. После входа обновляйте идентификатор сессии.

## PDO

```php
$stmt = $pdo->prepare('SELECT * FROM users WHERE email = :email');
$stmt->execute(['email' => $email]);
$user = $stmt->fetch();
```

Подготовленные запросы отделяют SQL-код от данных и защищают от SQL injection при корректном использовании.

!!! warning "Частая ошибка"
    Экранирование HTML и защита SQL решают разные задачи. Для SQL используйте параметры, для вывода в HTML применяйте контекстное экранирование.

## Как ответить на интервью

> PHP выполняется на сервере и формирует HTTP-ответ. Входные данные считаются недоверенными: я валидирую их, использую подготовленные запросы PDO, возвращаю подходящий статус и не показываю пользователю внутреннюю ошибку. Сессия хранится на сервере, cookie передает идентификатор клиента.
